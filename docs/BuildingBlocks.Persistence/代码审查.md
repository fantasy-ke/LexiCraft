# 持久化 BuildingBlocks 代码审查

- 审查日期：2026-08-13
- 范围：`BuildingBlocks.EntityFrameworkCore`、`BuildingBlocks.EntityFrameworkCore.Postgres`、`BuildingBlocks.MongoDB` 及受公共接口影响的直接调用链。
- 目标：修复正确性遗漏，收敛 DI/迁移/重试边界，并降低查询、反射和监控开销。

## 已修复问题

### P0：EF 软删除逻辑会丢失删除状态

原实现对 `Deleted` 实体调用 `Reload()`，但没有稳定地把删除转换为更新，容易丢失待写入的删除字段，甚至继续执行物理删除。现在只把 `IsDeleted` 和删除审计属性标记为已修改，既保留数据库行，也避免脱离跟踪的仅主键实体把其他列覆盖为默认值；SQLite 回归测试覆盖了这两种场景。

### P0：注册 DbContext 时构造临时 ServiceProvider

原 PostgreSQL 注册代码在 `AddDbContext` 中调用 `BuildServiceProvider()`，会创建第二套单例/作用域图，使 `IUserContext`、日志和其他 scoped 依赖来源错误。现在审计拦截器按 scoped 注册，并从当前 DbContext scope 解析。

### P1：迁移失败被吞掉

原迁移 worker 只记录异常，应用可能在 schema 未更新或 seed 未完成时继续启动。现在迁移与 seed 使用异步 scope、传播 `CancellationToken`，失败后重新抛出，测试覆盖 seed 异常向启动方传播。

### P1：Mongo 自定义配置节未被完整使用

原注册路径可能注册一个配置节，却从另一个固定节读取配置。现在统一按调用方传入的 section 绑定，并校验连接字符串、数据库名和连接池边界。

### P1：Mongo 异常映射可能被默认注册遮蔽

原注册使用 `TryAddSingleton<IProblemCodeMapper, MongoDbProblemCodeMapper>`；如果验证模块先注册默认 mapper，Mongo mapper 会被跳过，连接异常等错误只能返回通用 500。现在用 `Replace` 让 Mongo mapper 成为主映射器，并由它继续委托 `DefaultProblemCodeMapper` 处理非 Mongo 异常；重复注册也不会累计多个主映射器。

### P1：Mongo 全局映射重复注册

原逻辑每次注册 Context 都再次注册 BSON convention/serializer，多 Host 和测试进程可能抛出重复注册异常。现在通过线程安全的 `Lazy` 只初始化一次，同时保留全局 camelCase 和字符串枚举对嵌套文档的兼容。

### P1：Mongo 事务内读取绕过当前 session

原通用查询仓储只在写操作中使用 `MongoDbContext.Session`，事务内先写后读可能看不到同一事务中的变更。现在所有 Find、Count 和 LINQ 查询都绑定活动 session；分页在非事务场景并行，在事务 session 内串行，避免驱动不支持的同 session 并发操作。提交或回滚失败时不提前释放 session，调用方仍可继续完成事务收尾。

### P1：取消令牌在仓储、事务和业务调用链中丢失

EF/Mongo 仓储、工作单元、迁移、seed 及 Identity/Vocabulary/Practice/Files 的直接调用统一向底层传递 `CancellationToken`。业务请求取消时不再继续占用数据库连接执行无用 I/O。

### P2：查询和监控存在额外开销

- Mongo `Any`/`First` 限制最多读取 1 条，`Single` 最多读取 2 条。
- Mongo 非事务分页的 count/list 并发执行；事务分页绑定同一 session 串行执行，并移除同步 `CountDocuments`。
- 批量写入只枚举输入一次，空集合不再调用 `InsertManyAsync`。
- 强类型 ID 构造从每次反射改为每个泛型类型编译一次委托。
- 性能监控关闭时零记录，在并发记录下将内存队列精确限制为 10,000 条，读取时仅对快照做时间窗口过滤，避免并发清理误删新指标。
- 重试只处理明确 transient 的 Mongo 异常，避免认证/序列化/参数错误的无意义退避。
- Identity 初始化权限由逐条存在性查询改为一次集合查询，减少启动期数据库往返。

## 验证覆盖

新增 `BuildingBlocks.Persistence.Tests`，覆盖：

- EF 审计、UTC 时间、软删除字段隔离、分页参数及分页扩展取消传播；
- 强类型 ID 转换；
- PostgreSQL 连接字符串 fallback、缺失配置、迁移失败传播；
- Mongo 自定义配置节、异常映射替换与默认 fallback、重复注册、嵌套文档约定、数据库名、连接池校验和空批量写入；
- Mongo 监控开关、指标上限和时间窗口校验；
- Mongo transient/non-transient 重试和预取消行为。

## 保留风险与后续建议

1. `IRepository.DeleteAsync(predicate)` 在 EF 中使用 `ExecuteDeleteAsync`，按设计绕过拦截器并物理删除；本次为兼容未改语义，README 已明确警告。
2. Mongo 写操作发生超时后重试仍可能重复产生业务效果；需要由具体命令通过唯一索引、幂等键或事务补齐，基础组件无法安全猜测。
3. 普通 `MongoRepository<TEntity>` 默认使用类型名作为集合名，resilient 基类默认使用小写类型名；当前 Practice 仓储均显式传集合名。若未来使用自动仓储，需先统一集合命名契约，避免访问不同集合。
4. PostgreSQL 仍保留 legacy timestamp 开关以兼容历史数据；移除前需做数据库列类型和数据迁移审计。
5. 本次完成单元测试、项目构建和解决方案构建，不等同于真实 PostgreSQL/MongoDB 集成测试或负载基准。生产性能结论仍需结合真实索引、数据量、拓扑和网络延迟验证。
