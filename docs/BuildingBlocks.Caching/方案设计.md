# BuildingBlocks.Caching 重构方案设计

> 日期：2026-08-14
> 范围：`BuildingBlocks.Caching` 及其授权 Redis 调用方
> 原则：保持业务调用方式稳定，收紧实现边界，优先修复可证明的正确性和并发问题。

## 1. 目标与验收标准

本次调整解决四类问题：

1. **目录与类型边界**：接口、配置、锁、Redis 实现和缓存编排按职责存放；公共 API 仅保留调用方真正需要的契约。
2. **正确性**：值类型未命中、锁后二次读取丢配置、Hash TTL、不同 Redis 实例本地串值等问题有回归测试。
3. **并发与资源**：命名 Redis 连接只创建一个共享 `ConnectionMultiplexer`；竞争失败的连接不会泄漏；锁等待不依赖可回拨的系统时间。
4. **可取消与可观察**：异步 Redis I/O 和锁接口传递 `CancellationToken`，取消不被降级逻辑吞掉。

验收包括缓存测试、授权测试、持久化回归、Identity 定向构建、活动解决方案构建、依赖边界检查和 `git diff --check`。

## 2. 调整前发现

| 优先级 | 问题 | 风险 |
| --- | --- | --- |
| P0 | Redis 未命中以 `default(T)` 表达 | `int`、`bool` 等值类型会把未命中误判成命中，跳过工厂 |
| P0 | `HideErrors` 可吞掉调用方取消 | 请求已取消后仍可能执行回退或返回默认值 |
| P1 | 防击穿锁后二次读取重新解析/丢失选项 | 可能读取错误 Redis 实例或使用不同序列化配置 |
| P1 | 本地缓存键不包含 Redis 实例 | 相同键在命名实例之间串值 |
| P1 | Hash 写入与 `EXPIRE` 分两次执行 | 进程中断时可能留下永久 Hash |
| P1 | 部分字段读取未读取内部时间戳 | Hash 过期判断失效或使用不完整数据 |
| P1 | 并发首次访问可能创建多条 Redis 连接 | 重复连接、事件订阅和资源泄漏 |
| P2 | 实现类和序列化工具暴露为公共 API | 调用方容易越过门面，后续无法替换实现 |
| P2 | README 描述 Redlock、健康检查和不存在的注册重载 | 文档与代码契约不一致 |
| P2 | 连接池选项存在但不生效 | 运维人员误以为能控制连接数量 |

### 公共 API 决策

保留公共：

- `ICacheService`：业务缓存门面；
- `CacheServiceOptions`、`RedisConnectionOptions`：调用配置；
- `IDistributedLock`、`IDistributedLockProvider` 和锁异常：授权适配层及少量基础设施调用；
- `DependencyInjectionExtensions`：唯一注册入口。

改为内部：

- `CacheService`、`IRedisCacheStore`、`RedisCacheStore`；
- Redis 连接工厂和具体锁实现；
- JSON/MemoryPack/GZip 工具。

这避免调用方依赖 StackExchange.Redis 的实现细节，也使“是否使用本地缓存、Redis、锁和降级”统一由门面处理。

## 4. 实现方式与设计模式评估

### 4.1 门面模式

`ICacheService` 是面向业务的门面，组合本地缓存、Redis、锁、序列化和异常策略。调用方不应分别注入多个底层组件。

### 4.2 端口与适配器

`IRedisCacheStore` 是类库内部端口，`RedisCacheStore` 是 StackExchange.Redis 适配器。端口保持内部，是为了测试门面而不是为外部扩展建立第二套不稳定 API。

### 4.3 每次调用选项

`Action<CacheServiceOptions>` 保留现有兼容方式。实现只解析一次选项，并将同一对象贯穿首次读取、锁等待、二次读取、工厂和写入，避免阶段间配置漂移。

这不是全局 Options 模式的替代；`RedisConnectionOptions` 仍是进程级配置，每次调用选项只描述单个缓存操作。

### 4.4 连接复用

每个命名实例由 `ConcurrentDictionary<string, Lazy<IConnectionMultiplexer>>` 惰性创建并复用一个连接。`LazyThreadSafetyMode.ExecutionAndPublication` 保证并发首次访问只执行一次连接创建；失败项从字典移除，允许下次重试。

StackExchange.Redis 的推荐使用模型是共享 multiplexer，不应自行构造“连接池”。旧字段仅为配置兼容保留并明确不生效。

### 4.5 防击穿互斥

当前是单 Redis 实例互斥锁，不是 Redlock。Lua 脚本保证只在键不存在时写入带租期的所有权值，释放/续租校验所有权。获取等待使用 `Stopwatch`，并在零超时时执行一次尝试。

此实现适合短临界区的缓存重建，不适合作为长事务或跨区域一致性锁。

## 5. 已完成修改

1. 新增显式 `CacheReadResult<T>`，正确区分未命中与 `default(T)`。
2. `GetOrSetAsync` 每次调用只执行一次配置委托。
3. 锁内二次检查复用完整选项。
4. 本地缓存键按 Redis 实例分区。
5. Redis 操作和锁接口传递取消令牌；取消始终重新抛出。
6. 连接工厂使用并发安全的 `Lazy<IConnectionMultiplexer>`。
7. Hash 自动补读 `cache_timestamp`，动态 TTL 非正值回退基础 TTL。
8. Hash 数据和 TTL 在同一事务提交。
9. 分布式锁使用单调时钟、剩余时间限幅和零超时单次尝试。
10. 拆分 `CacheService.Hash.cs`，避免继续扩大主实现文件。
11. 底层实现和序列化器改为 `internal`，测试通过 `InternalsVisibleTo` 验证。
12. 删除未使用的直接 `Newtonsoft.Json`、`Microsoft.Extensions.Caching.Abstractions` 和重复 `MemoryPack.Core` 引用。
13. 替换失真的 README；历史示例从运行时编译排除。

## 6. 兼容性说明

- `ICacheService` 的现有方法签名保留；仅底层接口和实现类收口。
- 配置节 `RedisCache` 和命名实例格式保留。
- `EnableConnectionPooling`、`MaxConnectionPoolSize` 暂不删除，标记为废弃且明确无效果。
- Hash 内部字段 `cache_timestamp` 保持不变。
- 目录/命名空间从 `Configuration`、`DistributedLock`、`Factories`、`Serialization` 调整到 `Options`、`Locking`、`Redis.Connections`、`Redis.Serialization`；仓库内调用方已同步。

## 7. 后续单独任务

### P1：真实 Redis 集成与并发验证

- 使用 Testcontainers 或独立测试 Redis 验证连接竞争、断线重连、Hash 事务和锁所有权；
- 增加 100~1000 并发同键重建测试，记录工厂执行次数和 P95/P99；
- 验证取消、Redis 超时和进程关闭时连接释放。

### P1：取消令牌工厂重载

增加兼容重载：

```csharp
Func<CancellationToken, Task<T>>
Func<CancellationToken, Task<Dictionary<string, string>>>
```

保留旧重载并委托到新实现，逐步迁移调用方，避免闭包遗漏令牌。

### P1：Redis 异步预热

- 评估 `ConnectAsync` 和 `IHostedService` 预热；
- 明确启动失败策略：必须 Redis 的宿主启动失败，可降级宿主延迟连接；
- 为每个命名实例增加连接状态指标，不能在请求热路径同步建连。

### P2：Hash 元数据模型

当前时间戳按基础 TTL 判断重建。若动态 TTL 可大于基础 TTL，应保存实际过期元数据或仅依赖 Redis TTL，避免提前重建。该调整需要先定义兼容的 Hash 元数据版本。

### P2：锁管理 API 收口

审计 `ForceReleaseLockAsync` 的所有调用；若只用于运维，迁移到受控诊断服务或在下一主版本删除，避免业务代码绕过所有权释放锁。

### P2：本地缓存容量与可观测性

- 为 MemoryCache 增加 SizeLimit/Size 设计；
- 增加本地/Redis 命中率、工厂回退、锁等待、序列化大小和错误分类指标；
- 指标标签不得直接使用高基数缓存键。

### P3：示例和兼容字段清理

- 将 `Examples/` 移到独立示例或测试项目，删除无法编译的旧 API；
- 下一主版本移除两个无效连接池字段；
- 根据实际需求再决定是否提供官方健康检查扩展，不能先写文档后补实现。
