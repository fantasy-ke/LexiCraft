# 2026-08-10 MassTransit 默认启用与 RabbitMQ 连接修复

## 需求

- 排查 Practice 与 Vocabulary 启动时主动连接 `rabbitmq://localhost/` 并因认证失败持续重试的问题。
- 确认未配置 MassTransit 时应默认禁用；实际使用消息总线的服务补齐配置，不使用的服务移除注册。

## 代码事实

- `AddCustomMassTransit` 原先无启用判断；缺少配置节时会使用 `localhost:5672` 与默认账号并注册、启动总线。
- Practice 的完成练习处理器通过 `IEventPublisher` 发布练习完成和错词集成事件，确实依赖 MassTransit。
- Vocabulary 未发现 `IEventPublisher`、`IPublishEndpoint`、Consumer、Saga 或 Activity 使用，仅在启动入口误注册并保留项目引用。
- 当前本机 RabbitMQ 容器监听 `172.31.21.1:5672`；端口可达，原账号配置与容器不一致。记忆中不记录具体凭据。

## 实现与文档变更

- 为 `MassTransitOptions` 增加默认关闭的 `Enabled`，公共扩展在未显式启用时直接返回，不注册总线及相关后台服务。
- Practice 显式启用 MassTransit，连接本机 RabbitMQ；其未使用 Saga 与事件溯源，因此明确关闭这两项附加能力。
- Vocabulary 移除 MassTransit 启动注册和无用项目引用。
- Identity 已有消息发布与事件溯源/Saga 使用，补充显式启用并对齐同一 RabbitMQ 实例配置，保持既有行为。
- README 补充 MassTransit 为 opt-in 的配置契约和 `Enabled=true` 示例。
