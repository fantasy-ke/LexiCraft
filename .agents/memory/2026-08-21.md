## 修复 Identity 版本化路由嵌套异常

### 需求
- 修复启动时报错 `A versioned API group cannot be mapped as a nested group`，根因定位到 Identity 的版本化端点被普通外层路由组包裹。

### 代码事实与实现
- `ApplicationConfiguration.UseApplication` 原先通过 `app.MapGroup(string.Empty).WithResultDto()` 包裹 Identity、Users、Permissions 三个模块；模块内部再调用 `NewVersionedApi`，当前 API 版本化库禁止这种嵌套。
- 改为直接从 `WebApplication` 映射三个模块，避免版本化 API 组成为嵌套组。
- 将业务模块的 `WithResultDto()` 下移到 Identity v1/v2 和 Users v1 的版本化路由组；Permissions 继续保留 `WithoutResultDto()` 的原始响应契约。

### 涉及文件
- `src/microservices/Identity/Fantasy.Services.Identity/ApplicationConfiguration.cs`
- `src/microservices/Identity/Fantasy.Services.Identity/Identity/IdentityConfigurations.cs`
- `src/microservices/Identity/Fantasy.Services.Identity/Users/UsersConfigurations.cs`

## 修复 IdentityDbContext 待迁移模型变更

### 需求
- 处理 Identity 服务启动时 `IdentityDbContext` 抛出的 `PendingModelChangesWarning`，使启动迁移可以正常完成。

### 根因与实现
- `BuildingBlocks.EntityFrameworkCore.Postgres` 当前启用了 `Npgsql.EnableLegacyTimestampBehavior`，运行模型将 `DateTime` 映射为 `timestamp without time zone`；既有 Identity migrations 和数据库中的对应列仍是 `timestamp with time zone`。
- 使用 EF Core 工具生成迁移 `20260821103540_AlignIdentityModel`，将 Identity 相关 DateTime 列统一调整为当前运行模型的 `timestamp without time zone`，并同步更新 `IdentityDbContextModelSnapshot`。
- 未通过忽略 `PendingModelChangesWarning` 绕过问题，也未修改现有账号、密码、密钥或局域网地址配置。
