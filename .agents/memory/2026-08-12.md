## BuildingBlocks.Authorization 多服务权限重构

### 需求

重构 `BuildingBlocks.Authorization` 的权限验证和权限注册，使多服务场景统一通过 `LexiCraft.Services.Identity.Api` 验证当前会话与权限；审查现有端点是否遗漏权限保护，并确认 Redis 实现的一致性与可用性问题。

### 代码事实与决策

- 各服务保留本地 JWT 密码学验证，Identity 作为当前会话和用户权限的唯一权威来源。
- Practice、Vocabulary、Files 不直接读取 Identity Redis 或数据库，而是携带原始 Bearer Token 调用 Identity 内部验证端点。
- 权限定义集中到 `LexiCraft.Shared` 的 `LexiCraftPermissionDefinitionProvider`，判定采用精确权限匹配；父权限不再隐式授予子权限。
- 管理员旁路仅依据持久化的 `admin` 角色，不再依赖账号字符串。
- Identity 授权使用独立命名 Redis 实例 `OAuthRedis`；access token、refresh token 和当前会话指针均使用令牌哈希，不保存令牌明文；新格式使用 `authorization:v2:*` 版本化键，避免反序列化旧会话值。
- Redis/Identity 故障时授权 fail closed：会话失效返回 401、权限不足返回 403、授权依赖不可用返回 503。

### 实现与文档变更

- 拆分权限注册与 Redis 接入，新增本地/远程访问令牌验证、Identity 远程权限检查、授权同步锁和统一验证结果契约。
- 移除进程内权限缓存，Redis 保存完整权限快照并缓存空集合；回源与权限变更使用分布式锁，权限变更无法可靠失效缓存时拒绝写入。
- 修复命名 Redis 实例配置被全局选项覆盖的问题，使 `OAuthRedis` 的逻辑数据库和超时独立生效；新增版本化授权键，旧键按 TTL 自然过期。
- 新增 Identity `POST /api/v1/identity/permissions/validate`，补齐会话轮换、刷新、登出、权限查询与变更的一致性处理。
- 新增统一权限树、普通用户默认叶子权限、Files 权限常量和 8 个版本化 HTTP 端点授权。
- 新增用户权限唯一约束、权限长度/去重/默认权限回填迁移，以及用户角色持久化和历史角色回填迁移。
- 更新 Aspire、Compose、Dockerfile 和各服务认证配置，业务服务通过服务发现/内部地址调用 Identity。
- 新增 Authorization 测试项目和 `docs/BuildingBlocks.Authorization/代码审查.md`。

### 已知限制与待办

- Identity 和授权 Redis 是所有受保护业务请求的同步硬依赖，生产需要高可用、超时/503 监控和故障演练。
- 分布式锁租期固定 30 秒且无自动续租；需要监控临界区耗时。
- Identity 内部权限验证端点必须由部署/网关限制为服务网络访问。
- 多服务仍共享对称 JWT 密钥，长期应迁移到 Identity 私钥签名、业务服务只持公钥。
- Files 的公开 `/uploads`、旧 `/content` 和 Code First gRPC 是兼容边界，不能承载私有文件公网访问。
- 权限缓存 TTL 为 1 分钟，任何绕过 Identity 的直接数据库写入都会跳过主动失效。
- `authorization:v2:*` 键升级会使旧 access/refresh token 失效；发布时必须协调更新并重启全部 Identity 实例，避免新旧会话格式混跑，并要求用户重新登录。

### 数据库操作风险

执行迁移整理时，`dotnet ef migrations remove --no-build --force` 意外连接当前配置指向的 Identity 开发 PostgreSQL，并回滚了已有 `Initial` 迁移。之后已从 Git 恢复原始迁移文件，重新生成本次迁移，并把数据库架构迁移到最新版本。

当前只能确认数据库架构已恢复，不能确认回滚前的业务数据已恢复；原有数据可能已被删除，如需保留必须从备份恢复。后续迁移维护命令应使用隔离空库或显式设计时连接。
