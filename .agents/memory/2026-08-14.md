## 持久化基础组件目录与设计重构

- 新建 `BuildingBlocks.Persistence.Abstractions`，把 `IQueryRepository<>`、`IRepository<>`、`IUnitOfWork` 从通用 `BuildingBlocks.Domain` 移出；Identity、Vocabulary、Practice、Files 增加直接项目引用。
- `IMongoDbContext` 移入 `BuildingBlocks.MongoDB.Abstractions`，根 `BuildingBlocks` 移除 EF Core/MongoDB.Driver 包引用。
- EF 类型按 `Abstractions`、`Repositories`、`Transactions`、`Extensions` 分类；PostgreSQL 类型按 `Configuration`、`DesignTime`、`Migrations`、`Extensions` 分类；Mongo 类型按 `Abstractions`、`Context`、`Entities`、`Repositories`、`Errors` 等分类并同步命名空间。
- 删除公共仓储无法跨提供程序实现的 `Select<TTemp>()`、`QueryNoTracking<T>()`，并删除只被 EF 实现自身使用的双泛型仓储接口。
- 合并 Mongo 普通/Resilient 两套仓储继承树。读取统一经过性能监控；非事务读取使用 Mongo resilience；事务内读取绑定 session 并绕过局部重试；写入不做应用层盲重试。
- 增加 `IMongoResilienceService`，避免 Mongo 注册覆盖同容器其他 `IResilienceService`。
- 拆出 PostgreSQL `DefaultDataSeeder`；移除 EF `IServiceCollection` 扩展中无法使用的 HostBuilder 回调参数；修正 Files `Extentions` / `WithLexiCraftDbAccess` 命名。
- Practice 的 `AnswerRecord` 与 `PracticeTaskItem` 只作为 `PracticeTask` 聚合内嵌文档写入；删除没有写入路径的独立集合、只读仓储、DI 注册和索引。索引按真实查询重设为用户+状态+完成时间、用户+任务类型、用户+来源三个复合索引；Context 与仓储统一使用 `PracticeTasksCollectionName = "practice_tasks"`，修复原索引建在单数 `practice_task`、读写却发生在复数集合的问题；线上旧索引需独立核查清理。
- 文档：新增 `docs/BuildingBlocks.Persistence/方案设计.md`，追加 `代码审查.md`，并更新四个持久化 README。
- 验证：持久化测试 28/28 通过；`dotnet build src/LexiCraft.slnx --no-restore` 为 0 警告、0 错误。
- 保留项：`BuildingBlocks.Domain.Internal` 中公开领域原语的命名迁移、从公共仓储移除 `SaveChangesAsync`、Specification/Query Object 替换 IQueryable，均应独立实施以控制影响面。
