## 缓存与授权基础类库边界重构

- 需求：复审缓存和权限验证基础类库的目录、类库边界、接口设计、设计模式、遗漏缺陷和性能问题，先形成分步方案，再实施并给出后续独立任务。
- 代码事实：原 `BuildingBlocks.Authorization` 直接包含 Redis 实现并引用缓存项目，导致业务服务传递引入 Redis/MemoryPack；`IUserContext` 位于授权项目使 EF 审计依赖授权；缓存以 `default(T)` 表达未命中、锁后二次读取可能丢失选项、本地缓存未按 Redis 实例隔离、取消可能被隐藏、并发首次连接可能重复创建、Hash 写入与 TTL 非原子。
- 类库调整：新增 `BuildingBlocks.Authorization.Redis` 作为 Identity 专用适配层；授权核心按 `Abstractions`、`Contexts`、`Extensions`、`Options`、`Permissions`、`Policies`、`Tokens` 整理；缓存按 `Abstractions`、`Options`、`Locking`、`Redis`、`Services`、`Internal`、`Extensions` 整理；`IUserContext` 下沉到 `BuildingBlocks.Contexts`，EF Core 移除授权项目引用。
- 接口调整：保留接口、配置、权限定义、Attribute/Requirement 和注册扩展为公共 API；DI 具体实现、Redis 存储/连接/序列化实现收口为 `internal`，测试通过 `InternalsVisibleTo`；`PermissionDefinitionManager` 直接注入 Provider 集合，移除服务定位器。
- 缺陷与性能修复：显式区分缓存命中/未命中；每次调用只解析一次配置；锁后二次检查复用完整选项；本地键加入 Redis 实例；取消始终传播；连接按命名实例以 `ConcurrentDictionary + Lazy<IConnectionMultiplexer>` 单例复用；Hash 自动读取时间戳并事务化写入数据和 TTL；锁使用单调时钟、剩余时间限幅和零超时单次尝试；未知权限不能被管理员旁路；非 Bearer/空 Token 不再调用 Identity。
- 依赖清理：授权核心移除缓存引用和未使用的 `Newtonsoft.Json`；缓存移除未使用/重复的 `Newtonsoft.Json`、`Microsoft.Extensions.Caching.Abstractions`、`MemoryPack.Core`；核心 BuildingBlocks、Authorization、EF Core 和 Files 的传递依赖均未发现 Redis/MemoryPack。
- 文档：重写缓存/授权 README；新增 `docs/BuildingBlocks.Caching/方案设计.md`、`docs/BuildingBlocks.Authorization/方案设计.md`；授权代码审查追加 2026-08-14 复审；后续任务分为真实 Redis/Aspire 集成与压测、取消令牌工厂重载、异步 Redis 预热、内部权限端点服务身份、JWT 非对称签名、Hash 元数据、锁管理 API、可观测性和命名空间主版本迁移。
