# 2026-08-19 第一阶段基础架构优化

## 需求
- 执行基础架构审计后的第一阶段：清理受版本控制的敏感配置、建立密钥扫描、恢复前端类型检查、启用真实前端测试、增加最小 CI，并防止旧 HTTP 客户端继续扩散。

## 代码事实
- Aspire 入口为 `src/LexiCraft.Aspire.Host/AppHost.cs`，服务连接字符串和 AgileConfig 配置由 AppHost 读取并注入各服务。
- 前端原有 `test` 脚本为空，已有测试文件直接依赖 `vitest`，但项目未声明或配置 Vitest。
- 前端旧版 `src/utils/http.ts` 仍被 `src/apis/dict.ts`、`index.ts`、`member.ts`、`user.ts`、`words.ts` 使用；本阶段保留这些既有调用，不新增迁移范围。

## 实现/文档变更
- 清空受版本控制配置中的连接字符串、OAuth/消息队列/对象存储密钥、AgileConfig Nodes/Secret；Compose 改用必填环境变量；AppHost 删除本地 AgileConfig 硬编码 JWT 密钥并增加缺失配置的启动校验。
- 新增 `scripts/security/scan-secrets.mjs`，扫描受版本控制文件中的私钥、常见 Token、凭据 URI、连接字符串密码和结构化敏感配置；新增 `docs/configuration-secrets.md` 说明 User Secrets、环境变量、Compose 和凭据轮换要求。
- 修复前端 `vue-tsc` 暴露的 props 默认值、事件类型、组件泛型、iframe、统计模型等问题；为 `orderStatus` 补充响应类型。
- 安装并配置 Vitest，增加 Node 环境兼容的测试 setup；校准现有认证、错误解析和密码验证测试，使其验证实际行为。
- 新增旧 HTTP 客户端引用门禁 `src/UIs/lexicraft-vue-frontend/scripts/check-legacy-http-imports.mjs`，并标记 `src/utils/http.ts` 为仅兼容用途。
- 新增 `.github/workflows/ci.yml`，串联敏感扫描、生产后端构建、后端测试、前端依赖安装、旧客户端门禁、类型检查、Vitest 和构建。
- 同步更新 `AGENTS.md` 与长期记忆，移除“前端测试脚本为空/类型检查被阻塞”的过期事实，并固化新的 CI 与安全门禁。
