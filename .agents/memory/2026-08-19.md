# 2026-08-19 第二阶段网关与 API 契约统一

## 需求
- 执行基础架构优化第二阶段：固化网关公开路由契约，统一前端 API 基址和认证请求链，迁移能够由当前后端端点证明的调用，并阻止继续复制服务直连或虚假接口。

## 代码事实
- 网关对外路径为 `/identity/v1/*`、`/vocabulary/v1/*`、`/practice/v1/*` 和 `/files/*`，再分别转换到业务服务的 `/api/v1/{service}/*` 或文件服务根路径。
- Identity 当前用户资料更新契约只支持 `Username` 与 `Avatar`；旧 `user/*` 客户端中的邮箱、手机、密码等兼容接口没有当前后端路由证据，不能批量迁移。
- 浏览器运行时若未配置 `VITE_API_BASE_URL`，应使用同源网关；本地开发由 Vite 将四个公开前缀代理到 `VITE_DEV_GATEWAY_TARGET`，默认目标为 `http://localhost:5000`。

## 实现/文档变更
- 新增 `src/ApiGateway/Fantasy.ApiGateway/gateway-routes.contract.json` 与 `scripts/gateway/validate-route-contract.mjs`，校验 Development/Docker 路由、路径转换、集群目标及网关关键管道；CI 增加该契约门禁。
- 删除 Development 路由的固定 `Hosts: [localhost]`，使域名由实际部署环境决定，同时保留现有路径转换和目标端口。
- 新增 `src/config/apiRoutes.ts` 集中维护服务前缀和已验证端点；将认证客户端重命名为 `apiClient.ts`，Identity、Vocabulary、Practice、Files 共用一个 Axios 实例、Bearer Token、401 单次刷新和 `ResultDto` 归一化。
- 公开认证路径改为精确集合与 OAuth 前缀判断，避免业务路径仅因包含 `login` 等字符串而被错误视为匿名请求。
- `env.ts` 删除 `IDENTITY_API`、`FILES_API`，浏览器默认使用同源 `/`；Vite 为 `/identity`、`/vocabulary`、`/practice`、`/files` 增加可配置网关代理。
- 用户资料页改用已验证的 Identity 更新端点；删除旧 `user.ts` 中无调用者且无后端契约证明的方法，只保留仍有页面调用的兼容接口，并移除用户 Store 的失效资料回退链路。
- 同步更新网关路由说明、认证集成说明、方案设计、代码审查记录和 `AGENTS.md`。
