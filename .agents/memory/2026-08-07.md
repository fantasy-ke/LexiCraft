## 当前后端框架

### 基础运行层

- `src/LexiCraft.Aspire.ServiceDefaults/Extensions.cs` 提供 AgileConfig 接入、健康检查、服务发现、HttpClient resilience、OpenTelemetry 指标和链路追踪。

### 业务服务

- Identity：`src/microservices/Identity/`。包含登录、注册、验证码、刷新令牌、OAuth 初始化/回调、登出、用户资料、头像和权限端点；使用 JWT Bearer 与权限声明。
- Vocabulary：`src/microservices/Vocabulary/`。包含单词搜索、词库列表、按词库分页取词、词库导入、用户单词状态和薄弱词查询；使用 PostgreSQL 与 Redis。
- Practice：`src/microservices/Practice/`。包含创建练习任务、完成任务、提交答案；使用 MongoDB 与 Redis。
- Files：`src/microservices/Files/LexiCraft.Files.Grpc/`。提供 gRPC 文件服务、`/content?relativePath=...` 内容读取、`/uploads` 静态目录和 OSS 接入。

### API 路径事实

服务端代码定义的模块前缀为：

- Identity：`api/v{version:apiVersion}/identity`
- Vocabulary：`api/v{version:apiVersion}/vocabulary`
- Practice：`api/v{version:apiVersion}/practice`

当前已扫描到的主要端点：

| 服务 | 方法与相对路径 | 权限/说明 |
| --- | --- | --- |
| Identity | `POST login`、`POST register`、`GET users/captcha`、`POST refresh-token`、`POST logout` | 登录、注册、验证码和令牌流程；登录/注册/刷新允许匿名 |
| Identity | `GET/PUT users/info`、`POST uploadAvatar` | 用户资料和头像；需要认证/权限 |
| Identity | `GET oauth/{provider}/initiate`、`POST oauth/{provider}/callback` | OAuth 流程；回调允许匿名 |
| Identity | `GET permissions/{userId:guid}` 及权限增删改 | 权限管理 |
| Vocabulary | `GET words`、`GET word-lists`、`GET word-lists/{id}/words`、`POST word-lists/import` | 搜索、词库、分页取词和导入 |
| Vocabulary | `POST user-words/state`、`GET user-words/weak` | 掌握状态和薄弱词 |
| Practice | `POST /tasks`、`PUT /tasks/{taskId}/complete`、`POST /assessments/submit` | 练习任务和答案评估 |
| Files | `GET /content`、静态 `/uploads`、gRPC `FilesService` | 文件内容与对象存储 |

端点通常经过 `src/BuildingBlocks/BuildingBlocks/Filters/ResultEndPointFilter.cs` 包装成 `ResultDto`；`src/BuildingBlocks/BuildingBlocks/Shared/ResultDto.cs` 定义了 `Status`、`Message`、`StatusCode`、`Data` 和扩展字段。实际 JSON 字段大小写需要通过 `ConfigureJson` 或运行响应确认。

## 前后端联调清单

### 已确认的契约

1. 前端新认证客户端以 `/v1/...` 作为相对路径，并在配置中把 Identity 基址设为网关的 `/identity` 前缀。
2. 后端直接服务路由包含 `/api/v1/identity/...`、`/api/v1/vocabulary/...`、`/api/v1/practice/...`；是否由 YARP 自动补充 `/api` 和服务前缀，当前仓库无法从 `appsettings.json` 证明，因为其中 `ReverseProxy` 节点为空。
3. 前端认证客户端使用 `Authorization: Bearer`；后端业务端点使用 JWT/权限授权。
4. 后端登录/注册/刷新响应 DTO 当前定义为 `Token` 与 `RefreshToken`；前端同时存在 `token`、`accessToken`、`refreshToken`、`expiresIn` 多种假设。
5. 后端注册密码校验最低 6 位且要求字母和数字；前端认证配置要求 8 至 20 位并要求大小写与数字，规则不一致。
6. 后端统一结果包络是 `ResultDto`，前端 `auth.ts` 有对应类型；旧 `http.ts` 使用另一套 `code/msg/success/data` 包络。
7. 开发环境 CORS 使用允许任意来源；非开发环境要求配置明确的允许来源，前端部署域名必须纳入配置。

### 前端当前不一致或缺口

- `src/config/env.ts`、`src/utils/authHttp.ts`、`src/utils/tokenManager.ts` 的 API 默认值不统一；认证客户端可能回退到 Identity 直连端口，而普通客户端走网关。
- 网关本地没有可审查的 YARP 路由快照，前端无法仅凭仓库确认 `/identity/v1/...` 是否转换到服务端的 `/api/v1/identity/...`。
- `auth.ts` 暴露了邮箱验证、密码重置、OAuth 提供商列表/绑定、会话查询和撤销会话等方法；在当前扫描到的 Identity Endpoint 中未发现对应实现，需要后端确认“未实现、外置或旧服务提供”。
- `src/apis/words.ts`、`dict.ts`、`user.ts` 仍使用旧业务路径；尚未看到它们与当前 Vocabulary/Practice 版本化端点的一一映射。
- 当前前端 API 目录未形成清晰的 Practice/Files 客户端契约；需要补齐练习任务、提交答案、完成任务和文件内容读取的类型化模块。
- `ResultDto` 字段大小写、空数据和错误字段需要用真实响应固定；不能同时保留两种错误归一化规则。
- OAuth 回调需要确认前端 `redirectUri`、后端 OAuth 配置、网关前缀和 CORS/安全头是否一致。
