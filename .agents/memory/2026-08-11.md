## Aspire 健康探针取消误报修复

### 需求

- 修复 Aspire 编排启动时 `/health` 偶发 `TaskCanceledException`，被 Serilog 记录为 500 错误的问题。

### 代码事实

- `AddDefaultHealthChecks()` 当前只注册同步的 `self` 检查，`/health` 没有数据库或消息队列等慢速健康检查。
- `HealthCheckMiddleware` 将 `HttpContext.RequestAborted` 传给 `DefaultHealthCheckService.CheckHealthAsync`；Aspire 健康检查调用方在资源状态切换、停止或放弃请求时会取消该令牌。
- 日志中的 `TaskCanceledException` 因此属于调用方取消，不是服务内部健康检查执行超时；增加服务端延迟会延长请求并增加被取消概率。
- Aspire 13.4.6 的 `WithHttpHealthCheck` 没有公开初始延迟或请求超时参数；`WithHttpProbe` 的探针参数不会替代本地 AppHost 立即执行的 HTTP 健康检查。

### 实现与文件

- 修改 `src/BuildingBlocks/BuildingBlocks.SerilogLogging/Utils/SerilogRequestUtility.cs`。
- 当且仅当请求路径为 `/health` 或 `/alive`、异常属于 `OperationCanceledException` 且 `RequestAborted` 已取消时，将请求日志降为 `Debug`。
- 普通业务请求取消、健康端点真实异常和真实 5xx 仍保持 `Error`，没有吞异常或修改健康状态判断。

### 验证结果

- `dotnet build src\BuildingBlocks\BuildingBlocks.SerilogLogging\BuildingBlocks.SerilogLogging.csproj --no-restore`：通过，0 个错误；仅有既有 NuGet 多源警告。
- `dotnet build src\LexiCraft.slnx --no-restore`：通过，0 个错误；75 个既有 NuGet 包源和 Humanizer 版本约束警告。
- 临时行为验证通过：已取消的 `/health` 返回 `Debug`；已取消的业务接口仍返回 `Error`；健康端点真实异常仍返回 `Error`。
- `git diff --check`：提交前执行。
